## Decisions from discussion with Barry

- MegaDetector (currently Redwood v1000) stays frozen. Only the MEWC
  classifier is in scope, so synthetic data are snips, not full frames.
- First target: strengthen the existing low-count classes (minimum about 50
  images, against 20,000 to 200,000 for abundant classes). Adding new classes
  with tens of images comes second.
- Barry proposed first adapting SDXL to Tasmanian snips across many classes,
  then specialising it for rare classes. Adopted as Stage A (one LoRA across
  all classes) and Stage B (per-class, only where needed).
- Snips are pre-squared 600 px with no metadata (no camera, site or date).
  The production Tasmanian model is ViT-L/16 at 384 (`VTL`). No permanent test
  set exists, and the production run used the test folder for validation.
  Barry: "we're not wedded to any decisions going forward".
- Synthetic snips are generated at 512 px, then finished like real snips:
  Lanczos to 600 x 600, PIL default JPEG. They then enter `mewc-train`'s own
  loader (bilinear to 384), so the last two steps match real snips exactly.

## Pipeline audit (code read)

- `mewc-snip` v1.0.4 to current: exact MegaDetector box crop, then
  `visualization_utils.resize_image` (PIL `Image.Resampling.LANCZOS`, formerly
  `ANTIALIAS`) to 600 x 600, then `PIL.Image.save` with defaults (JPEG quality
  75).
- `mewc-train` 2.0.9 on `mewc-flow` 2.0.4 (TF 2.16.1 image, Keras 3.3.3 on JAX
  0.4.28, keras_cv 0.9.0, kimm 0.2.5):
  - `load_img` decodes with `tf.image.decode_png` (which also decodes JPEG)
    and resizes with `tf.image.resize` (bilinear, no antialiasing).
  - Training batches are cast to uint8 before RandAugment; validation and
    test images stay float.
  - Each epoch samples exactly `CLASS_SAMPLES` per class (with replacement
    when short) with a fresh seed, using categorical focal loss.
  - Frozen-head epochs come first, then progressive unfreezing with rising
    RandAugment magnitude and dropout. The best epoch is chosen by validation
    loss, and the default config sets `VAL_PATH` = `TEST_PATH`.
- Hugging Face `bwbrook/mewc_pretrained` holds `tas_ens_mewc.keras`,
  `vitb_mewc_case_study.keras` and others. These were probably trained on all
  available snips, so they must not seed pseudo-rare experiments (test
  leakage).

## Speed

| Test | Result |
|---|---|
| SDXL base generation, 512 px, 30 steps, batch 8, bf16 | 0.75 s/image, about 4,800 images/h, 10.6 GiB peak |
| SDXL UNet LoRA rank 64 training step, 512 px, bf16, gradient checkpointing, batch 16 / 32 | 19.0 / 20.8 images/s (1.46 / 1.34 h per 100k), 8.6 / 11.3 GiB |

The LoRA figures exclude data loading and assume cached VAE latents and
text embeddings, which is the planned design. A Stage A pass over 100k snips is
therefore about 1.5 h, not the 4 to 6 h estimated before measuring.

Untuned SDXL output for camera-trap prompts (`docs/figures/2026-10-20-sdxl-base-before.jpg`)
reads "camera trap snip" as screenshots and cartoons for devils and quolls,
and gives glossy stock-photo wallabies and birds. That is the baseline Stage A
must move away from.
