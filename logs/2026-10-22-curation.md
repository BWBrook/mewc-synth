## Embedding: CPU too slow, moved to the A100

`src/curate_embed.py` reads stored zip entries by offset (CRC-checked, no extraction) and matches
`embed.py` preprocessing (DINOv2-base CLS, bicubic 224, ImageNet normalisation, unit-normalised,
float16), so full-library embeddings are comparable with the working-set audit. Shards of 50,000
rows make it resumable.

CPU benchmark on deep-server (2 x Xeon E5-2683 v4, AVX2, 32 threads): 16.2 images/s, about 70 h for
the library. The A100 did the 1.07 M working set in 9 minutes, so the run is queued on ngx-gpu
behind the classifier screening (`curation/v1/curate_gpu.sh` waits for `QUEUE DONE`), using the
identical `index.parquet` pushed from deep-server. deep-server pulls the outputs back
(`curate_pull.sh`, polling every 5 minutes).

## Grouping

`src/curate_groups.py`: per class, exact all-pairs cosine on the GPU in 4,096-row chunks, upper-
triangle edges at cosine >= 0.90, connected components at 0.90 (the threshold calibrated visually on
21 October) and at 0.95. Per class: groups, singletons, share of snips in multi-snip groups, snips
retained at one or three per group, largest group, and nearest-neighbour cosine median and 90th
percentile. The full library has more frames per burst than the capped working set, so chaining
(giant components) is the main thing to check before any threshold is used for decisions.
